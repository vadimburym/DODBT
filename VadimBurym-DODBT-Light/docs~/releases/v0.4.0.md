# DODBT 0.4.0

Release date: 2026-10-12.

This release adds editor-only linked groups, graph search and copying, a root-result API, and optional decorators. The plugin in `main/source` and `example-project/Assets/VadimBurym-DODBT-Dots` is identical. DODBT uses Unity serialization and editor APIs without an Odin dependency.

## Installation and upgrade

```text
https://github.com/vadimburym/DODBT.git?path=/source#v0.4.0
```

The release includes a UPM tarball, source ZIP, validation ZIP, and SHA-256 checksums. Existing serialized field names and script GUIDs are retained. Existing trees can continue using `Tick`; recompile a graph after editing its behavior. Decorators are optional and require `DODBT_DECORATORS` for the intended build target. The example enables this symbol for Standalone and WebGL and supplies `Time.timeAsDouble` to timed trees.

## Runtime additions

- `TickWithStatus(context, state)` performs one traversal and returns the root's Success, Failure, or Running result. `Tick` retains its existing behavior.
- **Timeout** starts a deadline on entry. At or after the deadline it aborts an active child and returns Failure before ticking that child again. External Abort clears the attempt; zero duration fails immediately.
- **Cooldown** starts after the child reports Success or Failure. Until the deadline, subsequent attempts return Failure without entering the child. External Abort stops a running child without starting a new delay and retains an existing deadline.
- **Inverter** swaps Success and Failure, preserves Running, and forwards Abort to its active child.

Timed trees use `Tick(context, state, now)` or `TickWithStatus(context, state, now)`, where `now` is finite, monotonically nondecreasing time in seconds. Deadlines are checked only when a branch is visited; sparse ticks do not add a background scheduler. Timers are per agent. Construction and state initialization allocate their buffers; steady-state traversal reuses them.

Disabling the extension preserves graph data and rejects unsupported compilation/execution. Build checks cover enabled scenes, Resources, and preloaded assets. Custom pipelines, Addressables, and external bundles must validate their own dependencies. Sequential shared-tree use is supported; concurrent or reentrant traversal is not introduced.

## Editor additions

- **Linked groups:** create from a non-Root branch, duplicate from any instance, or unlink while retaining nodes. Serialized fields, leaf types, topology, and relative layout synchronize between instances. Each instance retains independent managed data; Unity asset references remain shared. Groups cannot overlap or nest.
- **Group visualization:** root icons, yellow highlighting of related instances and edges, and a Groups tab with names and instance counts. Root dragging previews member movement continuously; Escape cancels, and mouse capture loss finishes the move. Group metadata is absent from runtime assets.
- **Search:** match titles, kinds, leaf classes, and namespaces; navigate results in editing or Debug Mode.
- **Copy/paste:** copy individual nodes or selected blocks with internal connections, fresh GUIDs, independent managed references, and Undo/Redo. Ordinary copies do not remain linked.
- **Leaf inspector:** a dark type-selector row with a white leaf icon and always-visible root fields. Nested managed references retain foldouts and neutral object icons. Type pickers emphasize class names and mute namespaces.

Execution continues to follow node positions from left to right. These editor features do not introduce a separate execution-order setting.

## Fixes

- Replacing occupied single-capacity connections warns in the graph editor's own console, with node names and the one-parent/one-child restriction. Cycle and linked-group conflicts use that same internal console, without Unity Console warnings.
- Clipboard insertion rejects invalid topology and non-finite positions before changing the destination.
- Mixed deletion/disconnection across group instances combines edits before synchronization, preventing deleted members or connections from reappearing. Undo/Redo restores the complete edit.
- Ordinary edge hover keeps a stable appearance; linked-group highlights survive hit testing and selection changes.
- Root Leaf parameters no longer collapse after unrelated edits. Node deletion preserves surviving selection, and decorator changes in Details refresh inline settings.
- Read-only edge drops and incomplete endpoints do not change graph connections. Graphs without compiled assets can be edited safely.

The tests cover nested selectors, parallel abort state, decorator timing, independent agents, steady-state allocations, native serialization, compiler validation, linked groups, copying, search, Undo/Redo, and graph-console warning routing. Editor interaction tests exercise native pointer and keyboard events and require a graphics device.

The example player retains a ComputeBuffer disposal warning at shutdown. Unity 6 also reports an obsolete editor event API warning. WebGL browser execution, Android, iOS, consoles, macOS, Linux, and Windows IL2CPP were not validated for this release. Third-party inspector integration depends on the consuming project's drawers and overrides; installing Odin alongside DODBT has not been explicitly tested.

The validation archive contains sanitized XML results, build summaries, the Windows player log, and package file hashes. Machine paths and test environment data are excluded. To reproduce EditMode tests, enable Unity Test Framework 1.5.1, add `com.vadimburym.dodbt` to the package manifest's `testables`, and run the `VadimBurym.DodBehaviourTree.Tests` assembly with a graphics device. Example-only fixtures require the full example project.
