# Пример DODBT-Light на LeoECS

Небольшая 2D-сцена: игрок перемещается по карте, противник патрулирует, обнаруживает игрока, преследует его, отступает, перемещается в сторону и стреляет. Поведение задает дерево DODBT-Light; движение, сенсоры и оружие выполняются ECS-системами.

Это пример подключения плагина, а не рекомендация по архитектуре игрового проекта.

## Запуск

Пример поставляется в скрытой папке `Samples~`. После установки DODBT-Light импортируйте **Samples → LeoECS 2D Example** через Package Manager. Откройте `Example2D.unity` в импортированной папке и включите Play Mode. Управление — **WASD** или стрелки; подсказка показана внизу экрана. Открывайте сцену отдельно от боя DOTS.

Пример сохраняет **LeoEcsLite**, **LeoEcsLite.Di** и **ServiceLocator**. Odin Inspector, Zenject и VContainer не используются. У Light-плагина этих зависимостей нет: они нужны только игре-примеру.

При переносе примера в другой проект нужны Unity 6, URP, Unity UI (uGUI), Input System, AI Navigation, NavMeshPlus, LeoEcsLite, LeoEcsLite.Di и LeoEcsLite.UnityEditor, а также стандартные пакеты 2D Sprite, Tilemap и Tilemap Extras. Конкретные версии и Git-ревизии приведены в [DEPENDENCIES.md](DEPENDENCIES.md). Код примера включается только при наличии его основных зависимостей. Сам импорт не устанавливает пакеты и не меняет ProjectSettings.

Спрайты используют unlit-материал: отдельный 2D Renderer для сцены не требуется. Имя пользовательского слоя `Walls` создавать не нужно: физические запросы используют индекс 6, уже записанный в сцене. Игрок и снаряды сохраняют слои 8 и 7. Если в вашем проекте изменена матрица столкновений этих слоев, учитывайте ее при запуске примера.

## Структура

- `Example2D.unity` — готовая игровая сцена; отдельной загрузочной сцены нет.
- `BehaviourTree` — контекст, состояние, интеграция и сервис дерева; `Assets`, `Leaves`, `States` и `Comparisons` рядом.
- `Gameplay` — компоненты, системы, создание игрока/противников/снарядов, настройки и компоненты сцены.
- `Services` — ServiceLocator, ECS-миры, ввод и пулы.
- `Setup` — запуск сессии и регистрация зависимостей.
- `Content` — префабы, спрайты, конфигурации и данные рендеринга.
- `Editor` — подсветка точек патрулирования в Scene View.

## С каких файлов начать

| Файл | Назначение |
| --- | --- |
| `Setup/ExampleGame.cs` | Запуск и завершение сессии. |
| `Setup/GameInstaller.cs` | Регистрация сервисов и порядок ECS-систем. |
| `Setup/SceneInstaller.cs` | Ссылки на объекты сцены. |
| `Setup/GameSession.cs` | Инициализация, Update, LateUpdate и очистка. |
| `BehaviourTree/BehaviourTreeWarmUpSystem.cs` | Один runtime-BT на скомпилированный ассет. |
| `BehaviourTree/BehaviourTreeLeafsConstructSystem.cs` | Подключение миров и пулов к общим листьям. |
| `Gameplay/Enemies/EnemyFactory.cs` | Отдельные Context и State для каждого противника; подключение отладки. |
| `BehaviourTree/AiBrainTickSystem.cs` | Тик дерева агента через ECS. |
| `BehaviourTree` | `LeoEcsContext` и `LeoEcsLeafState`. |
| `BehaviourTree/Leaves` | Условия и действия дерева. |
| `BehaviourTree/Assets` | Редактируемый граф и его скомпилированный ассет. |

`LeoEcsLite.Di` внедряет миры, фильтры и пулы в ECS-системы. ServiceLocator связывает сервисы примера. Три мира разделяют игровые сущности, одноразовые события и состояния действий BT. Они принадлежат только примеру и освобождаются при остановке.

В примере сохранены существующие системы и игровая сцена. Удалены неиспользуемые ветки Save/Load/FixedUpdate и лишняя регистрация провайдера. Повторное включение ExampleGame создает новую сессию после очистки пулов, миров и сервисов. Одновременно поддерживается одна сессия этого примера; второй ExampleGame отключается с предупреждением.

## Дерево и отладка

Откройте `BehaviourTree/Assets/ExampleBrain.asset`. Граф привязан к паре `LeoEcsContext + LeoEcsLeafState`. В шапке можно независимо выбрать Context и LeafState; список предлагает только листья, совпадающие по обоим типам. Контекст помечен `[BtContext]`, состояние — `[BtLeafState]`. Старые типы без атрибутов также находятся через `ILeaf<TContext, TLeafState>`.

Для запуска примера не требуется `DODBT_DECORATORS`: отрицание проверки видимости задается имеющимся параметром самого листа. Декораторы в плагине доступны отдельно.

В Play Mode выберите противника или его дочерний объект в Scene View и нажмите **Observe** над ним. Либо откройте **Tools → VadimBurym → DODBT-Light → BT Debugger**: там видны подключенные агенты, их деревья и активные листья.

Подключение выполняется в фабрике после `FillInitialState`:

```csharp
#if UNITY_EDITOR
BtMonoDebug.Attach(enemyGameObject, compiledAsset, btState);
#endif
```

Компонент создается или переиспользуется автоматически. Системе тика дополнительный код отладки не нужен.

## Изоляция

Код находится в сборке `DODBT.Light.Example` и пространствах имен `DODBT.Light.Example.*`. Он не содержит автоматически запускаемых ECS-систем DOTS и не обращается к World DOTS. Запуск происходит только через ExampleGame сцены. Для изучения примера используйте его отдельную сцену: физика 2D и NavMesh остаются штатными сервисами Unity.
