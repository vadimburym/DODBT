# DODBT 0.3.0

Release date: 2026-10-10.

DODBT's graph editor, asset inspectors, runtime debug tools, and graph compiler now work without Odin Inspector or Odin Serializer. The standalone Unity package is published from `source/`; example gameplay code and its third-party dependencies are not included.

## Installation

In Unity, open **Window > Package Manager > Install package from git URL**:

```text
https://github.com/vadimburym/DODBT.git?path=/source#v0.3.0
```

The release also provides a package tarball for **Install package from tarball**, a source ZIP, and a validation ZIP. `SHA256SUMS.txt` records the asset checksums.

## Changes

- Native Unity serialization replaces compiler cloning through Odin. Compiled leaves remain independent snapshots and preserve nested polymorphic data, shared references, cycles, and Unity asset references.
- Native inspectors support inline node editing, the Details panel, collection editing, Undo/Redo, and read-only debugging.
- Searchable leaf and nested type selectors display `ClassName (Namespace)` without assembly names.
- Private `[SerializeField]` fields are visible when expanding leaves. Fields explicitly marked `[HideInInspector]` remain hidden.
- Graph validation reports missing nodes or leaves, cycles, duplicate GUIDs, invalid parallel thresholds, and node-capacity violations. A failed compilation retains the previous compiled tree.
- Graph views refresh after Undo/Redo and restore their asset selection after a domain reload.
- Tests are optional for package consumers and do not require the example project. Three integration tests are explicitly skipped if the example fixtures are absent.

See the [full changelog](../../source/CHANGELOG.md).

## Upgrade notes

Existing script GUIDs and serialized field names are retained. Existing example graphs and compiled assets were exercised by the regression suite.

Custom leaf classes must follow Unity serialization rules: use `[Serializable]`, `[SerializeField]` for private parameters, and `[SerializeReference]` for polymorphic fields. Odin-specific attributes and data types in consumer code are outside this package migration. Remove Odin from your project only if no other code or tools depend on it.

The [complete example project](https://github.com/vadimburym/DODBT/tree/example-project) keeps its unrelated gameplay and third-party tools separate from the package.

## Reproducing the tests

Install Unity Test Framework 1.5.1 for the test project. Add the package to the project manifest's `testables` list:

```json
"testables": ["com.vadimburym.dodbt"]
```

This uses Unity's [optional package test assembly setup](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/cus-pkg-development/cus-tests).

Run the `VadimBurym.DodBehaviourTree.Tests` EditMode assembly in Test Runner, or use the editor menu **Tools > VadimBurym > Verification > Run EditMode tests**. The menu saves results to `Logs/EditorVerification.xml` and keeps Unity open.

For a separate validation project, use:

```text
Unity.exe -batchmode -nographics -projectPath <project> -runTests -testPlatform EditMode -assemblyNames VadimBurym.DodBehaviourTree.Tests -testResults <results.xml> -logFile <editor.log>
```

The release validation archive contains sanitized test-result XML files, a build summary, and the verification-player log. Machine-specific paths are replaced with placeholders; test outcomes and skip reasons are preserved.
