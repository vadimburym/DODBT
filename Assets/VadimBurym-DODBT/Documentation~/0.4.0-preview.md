# DODBT 0.4.0 preview

This development version adds a root-result API, optional decorators, graph search, and node copying. It retains the ordinary left-to-right execution model and the existing `Tick` method. It does not include linked subtrees or execution history.

## Root result

```csharp
NodeStatus result = tree.TickWithStatus(context, state);
```

This performs exactly one traversal and returns the root's Success, Failure, or Running result. `Tick(context, state)` performs the same traversal and discards the result. Both work in players and the editor.

A custom leaf can use this API to execute another BT. Initialize a separate child BtState per agent and call site, inject child leaf dependencies, propagate the child's result, and forward parent OnAbort to the child tree. Do not store per-agent child state in a shared leaf instance. Prevent cyclic tree references in the integration.

## Optional decorators

Add `DODBT_DECORATORS` to Scripting Define Symbols for the build target. The editor's Add menu then includes Decorators / Timeout, Cooldown, and Inverter. Each requires exactly one child. Existing trees do not need decorators.

For a tree containing Timeout or Cooldown, pass time in seconds:

```csharp
NodeStatus result = tree.TickWithStatus(context, state, now);
// Or discard the result:
tree.Tick(context, state, now);
```

`now` is a finite, monotonically nondecreasing double from the caller's clock. The same timestamp is used throughout one traversal. Choose a game clock if pausing or changing game speed should affect timers, or an independent monotonic clock otherwise. Do not change clock origin or scale within an initialized agent state. Equal timestamps are allowed; backwards time, nonfinite time, and overflowing deadlines are rejected before executing children.

The overloads with a timestamp only exist when the extension is enabled. Calling the old overload on a timed tree reports an integration error. Inverter alone does not require time. State is independent for every agent; timer buffers are allocated at initialization and reused during ticks.

| Node | Behavior | External Abort |
| --- | --- | --- |
| Timeout | Starts a deadline on entry. Returns the child's result until the deadline; at or after it, aborts an active child and returns Failure before another child tick. Duration zero fails without entering the child. | Stops the active child and clears the deadline. The next activation starts a fresh budget. |
| Cooldown | First attempt is immediately available. After child Success or Failure, blocks further attempts for Duration and returns Failure without ticking the child. A Running child continues normally. The exact deadline permits another attempt. | Stops the active child without starting a new delay. An already established cooldown is retained. |
| Inverter | Success becomes Failure; Failure becomes Success; Running is unchanged. | Forwards Abort to an active child. It does not invert an abort into success. |

Abort preserves the existing leaf callback contract: an active leaf receives OnAbort, with no additional OnExit. Completed leaves receive no extra abort. Child MemorySequence/MemorySelector reset settings remain in effect; a decorator does not silently reinitialize their state or undo gameplay side effects. Call Abort before resetting or releasing a state that owns active actions. FillInitialState clears timer state for reuse; it does not clean up user-owned leaf data.

Cooldown starts at the tick where completion is reported, even if an external action finished earlier. Duration zero adds no delay. Repeated visits by an existing MemorySelector remain repeated visits; zero duration does not impose a once-per-frame execution limit.

### Sparse ticks and nesting

Timers are checked only when their branch is visited. Starting Timeout at 10.0 with duration 0.5 and next visiting it at 12.0 interrupts at 12.0. There is no background scheduler and no catch-up loop. Stop abandoned running branches explicitly with Abort. Long gaps cannot accumulate a burst of Cooldown attempts.

`Cooldown(Timeout(Action))` begins cooldown after a timeout Failure. `Timeout(Cooldown(Action))` immediately fails if the cooldown gate is closed. `Inverter(Cooldown(Action))` turns a closed gate into Success. `Inverter(Timeout(Action))` turns timeout Failure into Success; reversing these two wrappers does not.

A time-check leaf at the start of a regular Sequence can gate and interrupt a later action because regular Sequence checks from the left every tick. MemorySequence skips earlier successful checks while resuming a running child. A separate condition leaf does not automatically observe the later subtree's completion/abort to maintain the same attempt or cooldown lifecycle; that coupling must be implemented in context/gameplay code.

### Disabling the module

Serialized decorator descriptions and stable node IDs remain available when the symbol is removed. Their data is retained. Compilation of a graph containing decorators is rejected; runtime construction also rejects compiled trees requiring the missing extension.

The build check covers enabled build scenes, Resources, and preloaded asset dependencies. Trees delivered through custom build pipelines, Addressables, or external bundles must also be validated by those pipelines; runtime construction always checks compatibility. The extension symbol must match the intended player target. Tests and verification players are opt-in and do not become a dependency of ordinary players.

## Graph search

Use the search bar above the graph. It matches node titles, node kinds, leaf classes, and namespaces without case sensitivity. Space-separated words must all match. Matches are highlighted without moving nodes or changing execution order. Enter goes to the next result, Shift+Enter to the previous one, and Escape clears the query. Previous/Next buttons provide the same navigation. Search also works in Debug Mode and keeps runtime status borders visible.

## Copying

Select one node or a block, then use the graph's Copy/Paste/Duplicate commands and standard editor shortcuts. The Root is excluded. Copies receive new node GUIDs and independent serialized leaf data. Connections are retained only when both ends belong to the selection. Relative positions and internal child order are retained; insertion offsets the block and selects its new nodes. One Undo removes the insertion; Redo restores it.

Unity asset references are shared references, not duplicate assets. Managed-reference cycles and aliases within the copied snapshot are preserved. Copying a composite alone does not copy its unselected descendants. Incomplete/disconnected copies are editable, and normal compiler validation applies when connecting and compiling them.

The versioned clipboard supports compatible graphs in the same project and survives script reloads. Persistent Unity references use stable asset identifiers. Temporary objects are only supported while still alive in the same editor session. Missing types or missing referenced objects reject a paste before changing the destination. Clipboard data from a different project is rejected. Copies are independent and do not synchronize later changes.

Debug Mode permits searching and copying for inspection, but does not permit paste, duplicate, or cut.

## Validation

On Unity 6000.0.51f1, all 105 EditMode tests pass with decorators enabled and all 81 pass with decorators disabled. Both configurations pass with default indices and `DODBT_SMALL_SIZE`. Coverage includes sparse ticks, exact deadlines, nested decorators, abort propagation, independent agents, steady-state allocations, search, independent clipboard data, Unity references, and Undo/Redo.

The Windows x64 Mono player builds with High stripping, zero errors, and two URP shader warnings. The verification player exits with code 0 after serialization, runtime audit, root-result, and decorator smoke checks. The existing ComputeBuffer disposal warning remains at shutdown. The standalone package also imports into a project without Odin Inspector or Unity Test Framework installed.

The WebGL IL2CPP player also builds with High stripping, zero errors, and 11 NavMeshPlus/URP warnings. Browser execution has not been verified.

These automated checks do not replace interactive acceptance of graph editing in the target Unity project or validation on additional player platforms.
